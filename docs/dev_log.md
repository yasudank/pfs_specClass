# 開発記録（2026-10-06〜07、GB10 マシン）

時系列で、何を調べ、何が分かり、なぜその判断をしたかを残す。手法の定義は README.md、現状の要約は CLAUDE.md。

## 1. 手法の選定

- データ: pfsObject coadd 216,476 本（gaiafiller / observatoryfiller、大半は恒星）。ピクセルあたり S/N の中央値 3.3、
  S/N>5 は約 35%。DB の分類は STAR 108k / GALAXY 107k / QSO 1.4k だが、GALAXY のうち 1.1 万本が z>2 で低 S/N の誤判定が多い。
- 重み付き PCA をベースラインとし、本命を spender 型オートエンコーダ（χ² 損失、マスク・誤差を直接扱う、振幅は
  解析解、赤方偏移対応のデコーダ）＋潜在空間の密度推定（GMM）とした。異常度は S/N 十分位ビン内のパーセンタイル。
- 対照学習は、同じ天体を別の combination で観測したペアが約 5%（約 1 万天体）しかないため補助的な扱いとし、
  そのペアは評価（同じ天体の別観測が潜在空間で近いか）に使っている。

## 2. 前処理

- combination ごとに元の波長グリッドが違う（11251 / 11501 / 13293 px）ので、376–1268 nm、Δlnλ=3.5e-4 の共通グリッド
  （3474 ビン）に逆分散加重で再ビン。m アームは r アーム相当の分解能に平滑化。
- objId はファイル名だと丸められていることがある（gaiafiller）ので header から取る。ファイル名が
  `pfsObject_nan_4_<objId>_...` の 16 本は、正規表現を直して対応した。
- 大気輝線の残差は輝線の明るさのおよそ 3〜4%（PCA の残差から較正）→ sky_frac=0.04。
- bmn の欠損区間の縁（645–656、937–945 nm）に大きなスパイクがあるので、内部の欠損の両側 25 ビンを除外。

## 3. オートエンコーダの改良

- v1: m アームの有無で UMAP が分かれた（m アーム AUC 0.97）。bmn の欠損区間（656–703, 896–937 nm）のマスクの形を
  学習していた。
- v2: InstanceNorm を外し、粗くビン化した連続光（32 区間）を MLP に直接入力。r アームのスペクトルにも確率 0.5 で
  bmn と同じ欠損マスクをかけ、拡張の異なる 2 つの入力の潜在ベクトルが一致するよう一貫性損失を追加 → AUC 0.87、
  同じ天体の別観測の潜在距離 0.43→0.27。同じ天体で比べると、構成が異なるペアと同じペアの距離はほぼ等しく
  （0.900 と 0.887）、残る AUC は観測した天体集団の違いによるものと解釈した。

## 4. 調査で分かったこと

- **DRP の誤分類**: UMAP の星の領域にいる DRP の GALAXY（2,153 天体、GALAXY の 10%）は、Ca 三重線が z=0 で星と同じ
  割合で検出される（34.5% と 38.6%、銀河の領域では 0.7%）→ 星の誤分類。DRP の z は 0.19〜6.7 に散らばり、
  probaGalaxy は 1.0 に張り付く。一覧: `outputs/diagnostics/galaxy_in_star_region.csv`。
- **星と銀河の交差**: 2 次元 UMAP で混ざって見える部分の多くは射影による見かけ（10 次元では 550 天体が分離）。
  10 次元でも混ざる 183 天体は、n アームの段差や近赤外の負のフラックスなど同じ装置由来の形を共有していた。
- **1 µm の山**（ホットファイバー）: 930 nm で立ち上がり 970–990 nm がピーク、その後台地になる形。異なる visit・
  異なる天体（星と「銀河」）で同じ形が出る。各分光器の高 fiberId 側の端（610–671, 1274–1301, 1937–1952）と
  1132–1151 付近に集中（発生率 40〜60%、全体 7.4%）。原因は未確認（スリット端・検出器端の処理の可能性）。
- **bmnr の箱型のずれ**: m と r の visit を両方含む coadd（selected_run24/25）では、r だけの区間（656–703、
  896–937 nm）の明るさが他とずれる（15% 超が bmnr の 2〜4%）。例: objId 110531500621946746 は bmn_run26 /
  brn_run26 では STAR、selected_run25（bmnr）では GALAXY と DRP が判定。b/r のつなぎ目の段差は、指標が QSO の輝線や
  TiO の強い M 型星に反応するだけでフラグにしなかった。r/n のつなぎ目（950 nm）の 15〜20% の段差は bnr の 4.5% に
  あるが、QSO なども混ざるため未対応。
- **UMAP の島**（v4）: 島 1（約 260 天体、selected_run25 の bmn、visit 134908–134915）は、同じ天体の別観測が本体側に
  戻ることから装置由来（n アームの較正異常）。島 2（約 250 天体、selected_run24）は TiO の強い晩期 M 型星らしく、
  この天域（RA 8–24°, Dec 30–48°）は selected_run24 しか観測していないため、本物の集団である可能性が高い（未確定）。
- **赤方偏移**: 観測波長のまま学習しても、銀河の帯に沿って z が変化し、潜在 10 次元から kNN で
  NMAD(Δz/(1+z))=0.023 で予測できる。DRP の z は 0.87〜0.89 に約 30 倍の集中があり（552 本が selected_run25 の bmn）、
  bmn の欠損区間の縁のスパイクを [OII] と [OIII] と誤認している可能性が高い（波長の一致からの推測）。

## 5. 品質フラグとホット visit

- v3: NARM_BUMP / NARM_STEP / HOT_FIBER / NEG_BLUE / NEG_NIR を導入。ホットファイバーは二項検定（単独、および隣接
  ±3 本をまとめて）。段差だけ（NARM_STEP）は本物の赤い星が多いので、ホットファイバー上のときだけ n アームを落とす。
- v4: MIXED_RM（bmnr の r だけの区間を落とす）。箱型のずれのある 101 本で χ² 3.54→2.61、異常度 0.99 超 27%→13%。
- ホット visit（visit_quality.py）: アームを 1 本ずつ隠して他のアームから予測し、20 nm ビンの相対残差を露出・カメラ
  単位で集計する。試行錯誤:
  1. 全 unit がホットになった → アーム全体の予測自体に系統的な偏りがあるため、基準を差し引く必要があった。
  2. 潜在空間の近傍の残差を差し引いたが、全スペクトルからエンコードした潜在ベクトルは装置由来の形を含み、
     同じ異常を持つ近傍が選ばれて打ち消された → そのアームを隠してエンコードした潜在ベクトルで近傍を探す。
  3. bmn と bnr で系統的な違いがあり、bmn_run26 の 71% が HOT_VISIT になった → 近傍・基準をアーム構成ごとに分けた。
  4. 閾値: 5σ・5 倍では島 1 の 39%、4σ・4 倍で 78%（HOT_VISIT は全体の 10.5%）、3 倍だと 89% だが 17% に増える。
     4σ・4 倍を採用。
- 学習データの選び方: 「HOT_VISIT を全部除外」は観測構成に偏った除外になる（v5 を中止）。visit は視野・run・
  構成と結びつくので、visit 単位の除外は天体集団を偏らせる。ファイバー単位の除外は偏らせない。

## 6. v4 / v6 / v7 の比較と結論

- v6（強い除外、学習 73,533 本）と v7（NEG_* だけ除外＋全マスク、83,501 本、シード 0 と 1）を比べた
  （数値は CLAUDE.md）。v7 と v7_s1 の差（シードだけの違い）が、モデル間の差と同程度だった。
- したがって学習データの選び方の良し悪しは、1 回ずつの比較では判定できない。除外を強める利点は見えず、QSO の
  再現率は除外すると下がる傾向（n=131 で統計的には弱い）。v7 の構成を既定にする方針を提案（ユーザーの判断待ち）。
- ホットファイバー AUC は約 0.70 から下がらない → 次は構造的な対策（装置の情報を条件にしたデコーダ、敵対的損失）。
